# 拆子问题结论 · decompose_v1

> 2026-09-27。代码 `src/answer.py`（`--decompose d2 --sub-k 5`）。协议：`reports/decompose_v1_protocol.md`、`dataset/blind_v6_protocol.md`。
> 明细：`reports/decompose_dev.md`、`decompose_v6.md`、`split_recall_dev.md`、`split_recall_dev_other.md`、`split_recall_v6.md`。

## 问题

单次 RAG 便宜，但在一句话连问好几件事的题上明显输给 Agent；路由也没能省钱（`reports/route_summary.md`）。能不能让单次 RAG 自己多检索几次，用接近它的成本，拿到接近 Agent 的完整度？

## 做法

一次**不带思考**的调用，把问题改写成最多 4 个检索词；原问题的前 5 块和每个检索词的前 5 块轮流合并，再用原来的提示词 p2 生成一次答案。总共两次模型调用，没有循环。

开发只用已经看过的集合，定下配置后再生成新的一批题 blind_v6，只跑一次。

## 开发时发现的事

1. **d1（口语子问题）没用。** 把问题拆成“太保阿基米德保险期间到多大岁数？”这类子问题，v3、v5 上与单次 RAG 持平。
2. **整条条款也没用。** 条款中位数只有 145 字，前后各带 1 块已经覆盖；这不是差距的来源。
3. **差距在“第二条证据”。** 需要两条及以上证据的题，Agent 几乎都能找全（v3 9/9、v5 7/8），单次 RAG 只有 3/9、1/8。
4. **Agent 赢在检索词的写法。** Agent 自己写的检索词是“保险期间 保障期限”“保险金给付 扣除 未偿还贷款本息”这类条款用语，还会补查疾病定义和较轻一档。d2 让拆分调用照这个方式写检索词，多证据题的召回提高到 6/9～7/9、6/8。
5. 因此原来的判断“单次 RAG 只答了第一问”只说对了一半：根本原因是口语问题的向量检索找不到第二条条款，模型没有证据可答。

## 结果

| 集合 | 单次 RAG | 拆分 d2 | Agent | 拆分成本 / Agent | 中位延迟：拆分 / Agent |
|---|---|---|---|---|---|
| 开发集合计（91 道可回答题） | 62/91 | 71/91 | 80/91 | 40%～53% | 接近 |
| **blind_v6（独立检验）** | **10/17** | **14/17** | **15/17** | **51%** | **13.8 / 16.4 秒** |

blind_v6 上其他指标：

- 拒答题：单次 RAG 2/3，拆分 3/3，Agent 3/3。
- 忠实：单次 RAG 20/20，拆分 20/20，Agent 19/20。
- 多证据题“全部证据都在上下文”：单次 RAG 6/13，拆分 11/13。
- 每千题：单次 RAG $1.10，拆分 $1.54，Agent $3.03。

事先写下的 5 条预测全部成立：

| 预测 | 结果 |
|---|---|
| 1. 答对数比单次 RAG 多 2 题及以上，但不超过 Agent | +4，比 Agent 少 1 |
| 2. 成本是 Agent 的 35%～65%，是单次 RAG 的 1.1～1.6 倍 | 51%，1.40 倍 |
| 3. 多证据题的完整召回高于单次 RAG | 11/13 对 6/13 |
| 4. 不忠实答案不超过 1 个 | 0 个 |
| 5. 中位延迟不高于 Agent | 13.8 秒对 16.4 秒 |

按事先定的规则（答对数 ≥ Agent − 2，且成本 ≤ Agent 的 60%），**拆分 d2 可以作为成本敏感场景的默认**。

## 结论

1. **拆分 d2 以约一半的成本，拿到了 Agent 的大部分完整度。** 在独立的 v6 上比 Agent 少 1 题，成本 51%，延迟更低。
2. **Agent 仍然是准确率最高的选择。** 两套都跑过的 6 个集合里，Agent 答对数都不低于拆分。剩余差距还没有逐题分析；v6 上多证据题仍有 2 题拆分没找全证据，Agent 还能按条款号读全文。
3. **推荐配置因此变为：** 在意成本就用拆分 d2；在意准确率、或者问题需要多步查找，就用 Agent。不再推荐路由。
4. 拆分也有回退：开发集 blind_v2.1 的 c08 从 correct 变成 incorrect（没检索到“重疾给付后合同终止”，却断言条款没有约定）。

## 局限

- v6 只有 20 题，14 对 15 的差别在噪声范围内；只跑了一次。
- 出题模型 longcat-2.0 调用失败，按事先定的替补换成 kimi-k2.6，与 v3 的 kimi-k3 同一家族。omen-alpha 的底座无法核实。
- 所有检验集都是模型出的题，不一定代表真实用户的问题分布。
- 拆分和生成用的是同一家模型（DeepSeek）；评委是 GLM，没有换过。
