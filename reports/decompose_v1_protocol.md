# 拆子问题 v1 协议（先提交，后在 blind_v6 上运行）

> 2026-09-27 写定。本文件与 `src/answer.py`（`DECOMPOSE_PROMPTS["d2"]`）、`dataset/blind_v6_protocol.md` 一起提交，提交时 blind_v6 还没有生成。

## 为什么做

路由没有比“全部走 Agent”更划算（`reports/route_summary.md`）。单次 RAG 在一句话连问好几件事的题上输给 Agent。原来的判断是：一次检索只能拿到第一个子问题的证据。

## 开发过程（只用已经看过的集合）

| 尝试 | 做法 | 结果 |
|---|---|---|
| d1 | 把问题拆成口语子问题，每个子问题各检索 3 块，并把子问题列给生成模型逐一回答 | v3 9/18、v5 9/17，与单次 RAG 持平 |
| 整条条款 | 命中的条款不超过 3000 字就整条带上（像 Agent 的 read_clause） | 几乎没有改变上下文：条款中位数只有 145 字，前后各 1 块已经覆盖 |
| **d2** | 不写子问题，写**关键词式的检索词**，用条款里的说法，并补查答案依赖的条款（疾病定义、较轻一档、申请与给付） | 多证据题的“全部证据都在上下文”明显提高，端到端见下表 |

诊断：多证据题里，Agent 能把每一条证据都找到（v3 9/9、v5 7/8），单次 RAG 只有 3/9、1/8。d1 的口语子问题只提高到 5/9、2/8。对比 Agent 的检索词后发现，差别在措辞：Agent 写的是“保险期间 保障期限”“保险金给付 扣除 未偿还贷款本息”这类条款用语。明细见 `reports/split_recall_dev.md`、`reports/split_recall_dev_other.md`。

## 定下来的配置：gen_v4_d2

- 拆分：deepseek-v4.1-flash，**不带思考**，提示词 `d2`，最多 4 个检索词。
- 检索：原问题前 5 块，加上每个检索词前 5 块（`--sub-k 5`），轮流合并、去重；检索词里没写产品名时，沿用原问题的产品过滤。
- 上下文：同条款前后各带 1 块，字数预算 12000。
- 生成：与 gen_v3_p2 相同（提示词 p2，带思考），检索词不交给生成模型。
- 命令：`uv run python src/answer.py --run-name gen_v4_d2_blind6 --golden golden_blind_v6.jsonl --emb bge-m3_index_text_blind6 --decompose d2 --sub-k 5`

## 开发集上的结果（`reports/decompose_dev.md`）

| 集合 | 单次 RAG | 拆分 d2 | Agent | 拆分成本 / Agent 成本 |
|---|---|---|---|---|
| golden_v2 | 28/30 | 29/30 | 29/30 | 53% |
| blind_v1 | 7/14 | 9/14 | 12/14 | 40% |
| blind_v2.1 | 10/12 | 9/12 | 10/12 | 41% |
| blind_v3 | 9/18 | 13/18 | 15/18 | 48% |
| blind_v5 | 8/17 | 11/17 | 14/17 | 52% |
| **合计** | **62/91** | **71/91** | **80/91** | |

- 回退：blind_v2.1 的 c08 从 correct 变为 incorrect，且判为不忠实（没检索到“重疾给付后合同终止”，却断言条款未约定免交保费）。
- 延迟：拆分调用约 3 秒，生成的上下文更长，中位延迟与 Agent 接近（v5 上 12.2 秒对 13.3 秒）。

## 预测（在 blind_v6 上运行之前写下）

1. **准确率**：拆分的可回答题答对数，比单次 RAG 多 2 题及以上，但不超过 Agent。
2. **成本**：拆分的成本是 Agent 的 35%～65%，是单次 RAG 的 1.1～1.6 倍。
3. **证据召回**：多证据题上“全部证据都在上下文”，拆分高于单次 RAG。
4. **忠实度**：拆分的不忠实答案不超过 1 个。
5. **延迟**：拆分的中位延迟不高于 Agent。

## 怎么下结论（事先定好）

- 拆分的答对数 ≥ Agent − 2，且成本 ≤ Agent 的 60%：拆分可以作为成本敏感场景的默认，写进 README 的推荐配置。
- 否则：默认仍是全部走 Agent，拆分作为便宜的备选记录下来。
- 无论结果如何，d2 的提示词和参数在 v6 上跑过以后都不再修改；要改就升为 d3，并换一批新题验证。
