## 流程

1. **先锁题，再标注。**
   - 写题时没有打开 PDF、chunks，也没有运行检索。题目单独提交（`f10e5c2`），标注是另一次提交（`9e6f7be`）。
   - 这批题是半盲的：作者是 AI，之前见过条款和检索结果。为避免重复，写题时看过已有题目列表。
   - BACKLOG 原本希望 blind_v2 由学习者本人写。这批题不能替代那一版，只能算“AI 写的第二批盲测”。
2. **标注方法。** 用脚本在文本块全文里匹配关键句，确定条款号和页码。脚本会断言两件事：关键句确实存在；拒答题的否定证据确实搜不到。标注过程没有用任何检索器。
   - c16 写题时预判是条件题，标注时发现条款没写投保人身故后怎么办，改为拒答题。改动写在题目的 `label_note` 字段里。
3. **只验证，不调参。**
   - 用的是已经定下来的配置：单次 RAG 用 p2 提示词加上下文扩展；Agent 用 a2 提示词加护栏。评委用 j2。
   - 每个配置只跑一次，结果出来后没有改任何配置。

## 结论

1. **Agent 的优势在 blind_v2 上没有复现。**
   - 两个配置只差 1 题。12 题的样本里这在噪声范围内，结论只能是“持平”。
   - Agent 的成本约为单次 RAG 的 3 倍，中位延迟约为 2 倍。
2. **blind_v1 上的差距可能被高估了。** BACKLOG 里早有这个担心：a2 提示词里的例子来自 blind_v1 的失败题，blind_v1 已经参与过调参。blind_v2 的结果和这个担心一致。
   - 这不说明 Agent 没用：golden 和 blind_v1 里跨条款、多条件的难题比例更高。
   - 但 blind_v2 说明，简单题和中等难度题上，单次 RAG 已经够用。
   - 这支持 BACKLOG 里的路由方案：简单题走单次 RAG，对比题和多条件题走 Agent。
3. **失败集中在“答不全”，没有编造。** 两个配置的忠实度都是 100%。
   - c09（理赔时限）：两个配置都只答了核定时限，漏了付款时限或拒赔通知时限。
   - c08（国寿交费期间得重疾）：Agent 只讲了投保可选责任二时保费豁免，漏了没投保可选责任二的情况。
   - c14（乙肝能否投保）：单次 RAG 正确拒答，但漏了“须如实告知”。
4. **检索只漏了 1 题（c06，国外医院确诊）。** 证据排在第 67 名。原因是问题里的“国外”在条款里找不到对应的词。
