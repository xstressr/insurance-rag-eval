# 路由 v2 协议（先提交，后在 blind_v5 上运行）

> 2026-09-27 写定。本文件与 `src/route_llm.py` 一起提交，提交时 blind_v5 还没有生成。

## 为什么要有 v2

路由 v1 在 v2.1 + v3 上的结果（`reports/route_v1.md`）：

- **级联**：答对 24/30，但成本比全部走 Agent 还高。原因是答对的单次 RAG 答案里，也常顺带写“片段未提及”，于是 36 题里升级了 23 题，其中不少是白白升级。
- **按形态分流**：只数问号，漏掉了“可以吗，要咋操作？”这种一个问号里有两问的题。
- **理论上限**：27/30，每千题 $1.98。空间很大，但靠关键词规则抓不住。

## 规则

- 设计集：开发集、v2.1、v3 共 87 题。结果见 `reports/route_v2_design.md`。
- 判断模型：deepseek-v4.1-flash，提示词见 `src/route_llm.py`。
- 定下来的主策略是 **llm_post（答后检查）**：先跑单次 RAG，再让判断模型检查答案有没有漏掉子问题。满足下面任一条就升级给 Agent：
  - 某个子问题没有回应；
  - 答案对条款通常会写的内容说“片段未提及”。
- 同时报告 **llm_pre（答前分流）** 和 **llm_pre_then_post（先分流、再检查）**，作为对照。

设计集上的结果：

| 集合 | llm_post 答对 | 全部走 Agent 答对 | llm_post 成本 | 全部走 Agent 成本 |
|---|---|---|---|---|
| 开发集 | 42/44 | 41/44 | $1.59 | $2.25 |
| v2.1+v3 | 25/30 | 25/30 | $3.34 | $3.47 |

## 预测（在 blind_v5 上运行之前写下）

1. **准确率**：llm_post 的可回答题答对数，不低于“全部走 Agent”减 1 题。
2. **成本**：llm_post 的成本是“全部走 Agent”的 70%～100%。v5 的出题方式与 v3 相同，题目多半一句话连问好几件事，所以省得不会多。
3. **路由 v1**：级联的成本仍然不低于“全部走 Agent”的 90%；按形态分流的答对数，仍低于“全部走 Agent” 2 题以上。
4. **延迟**：llm_post 的中位延迟高于“全部走 Agent”。被升级的题要依次经过单次 RAG、判断、Agent 三步。
