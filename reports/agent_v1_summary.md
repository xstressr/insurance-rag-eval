# 检索 Agent · agent_v1

> 2026-09-26。手写工具调用循环（`src/agent.py`，版本 a1），模型 `deepseek-v4.1-flash`，最多 6 轮工具调用。
> 工具：`search`（语义检索，可限定产品）、`read_clause`（读整条条款）、`final_answer`。回答规则沿用 p2。
> 查询向量由本地向量服务（`src/embed_server.py`，bge-m3 常驻 GPU）实时计算，与离线向量的余弦相似度为 1.0。
> 对照组：gen_v3_p2（单次检索 + 上下文扩展 + p2）。评委 j2（GLM-5.3，max 思考强度）。

|---|---|---|---|---|

盲测可回答题的正确率从 50.0% 升到 **92.9%**；证据进入上下文的比例在两个集合上都是 100%。

## 新出现的问题

1. **忠实度首次下降（3 题）**：q032 结尾补了一句“实际保费以保险单为准”，b09 对各产品的覆盖范围做了片段外的概括，b18 说“欠款会影响退还金额”。答案越长，越容易夹带没有依据的补充。其中 b18 那句可能有条款 8.4“未还款项”作依据，评委判定待人工核对。
2. **不按格式结束**：盲测 7/18、golden 3/33 的回合里，模型直接输出文字，没有调用 `final_answer`。循环兼容这种情况，但说明它对工具协议的遵守并不稳定。
3. **工具参数出错 4 次**：典型错误是把 `products` 写成 `product`。程序校验拦截后把错误信息返回给模型，模型下一轮都自行改正了，没有任何一题因此失败。
4. **工具名被截断**（开发时发现）：`search_clauses` 会被写成 `search_clause` 或 `search_cl`，改成短名 `search` 后稳定。

## 结论（AI 起草，待学习者确认）

1. **多条款问题的瓶颈不在排序，而在“一次查询”本身。** 重排把检索指标提高了，但端到端持平；Agent 让模型按缺什么查什么，盲测正确率从 50% 提到 93%。
2. **代价是 4～7 倍的输入 token。** 可以考虑路由：简单题走单次 RAG，对比题或多条件题走 Agent。
3. **Agent 让答案更完整，也让答案更长，编造的风险随之上升。** 忠实度从 100% 降到 94%，下一版提示词要约束“只写有片段依据的补充”。

## 严重局限：盲测已被污染

- Agent 系统提示里“一般规定和例外、犹豫期内和犹豫期后、权利和限制”这几个例子，直接来自盲测的失败题（b07、b18、b04）；冒烟测试也用了 b04 和 b18。**盲测上的 92.9% 很可能偏高。**
- golden_v2 上的 100% 同样是在见过的数据上取得的。
- 所以 **blind_v2 的优先级应当提高**：它是判断 Agent 是否真正有效的唯一干净证据。
- 每个配置只跑了一次；评委是 LLM，只经过 15 题校准。
