# 改进前后对比

> 2026-09-27。这里只汇总每一步“改了什么、换来什么、代价是什么”。数字全部来自 `reports/` 里的自动报告，结论和逐题分析见对应的 `*_summary.md`。
> 表中用到的简称：
> - Hit@5：前 5 个检索结果里有没有证据。
> - 正确：可回答题中被评委判为完全正确的题数。
> - 盲测 v1：golden_blind_v1，已被污染。
> - 盲测 v2：golden_blind_v2，目前唯一没参与过决策的集合。

## 一、检索（第 2～3 周）

| 步骤 | 改动 | golden_v1 Hit@5 | 盲测 v1 Hit@5 | 结论 |

| bm25_v1 | 手写 BM25，jieba 精确模式 | 51.7% | - | 基线 |
| bm25_v2 | 加产品过滤 | 51.7% | - | Hit 不变，MRR 从 0.369 升到 0.381 |
| bm25_v3 | jieba 搜索引擎模式 | 62.1% | - | 长词拆开后召回提升 |
| bm25_v4 | 保险词典 v2 | 62.1% | 50.0% | 基本不变 |
| **dense_v1** | bge-m3 向量检索 | **96.6%** | **85.7%** | 提升最大的一步 |
| hybrid_v1 | BM25 + 向量，等权 RRF 融合 | 79.3% | 64.3% | 更差：BM25 把好结果挤出了前 5 |
| hybrid_v2 | 加权 RRF（按事先定好的规则选参） | 100% | 78.6% | 在开发集上过拟合，盲测更差，放弃 |

## 四、上线前（第 6 周）

| 步骤 | 改动 | 结果 |
|---|---|---|
| 权限与隔离 | 身份由调用方传入；先按权限过滤再检索；“不存在”和“无权访问”返回同一句话 | 安全用例 12/12。模型在 4 个用例里尝试了越权调用（s01、s02、s04、s05），全被工具层拦住 |

## 五、最终两套配置对比

| | 单次 RAG（gen_v3_p2） | Agent（agent_v3_guard） |
|---|---|---|
| golden 正确 | 28/30 | 29/30 |
| 盲测 v1 正确 | 7/14 | 12/14 |
| **盲测 v2 / v2.1 正确** | **10/12 / 10/12** | **9/12 / 10/12** |
| **盲测 v3 正确** | **9/18** | **15/18** |
| 忠实度 | 100% | 97%～100% |
| 中位延迟（golden / 盲测 v2 / 盲测 v3） | 4.0 / 6.1 / 11.8 秒 | 7.9 / 13.1 / 16.8 秒 |
| 每千题成本（golden / 盲测 v2 / 盲测 v3） | $0.67 / $1.06 / $1.40 | $1.79 / $3.28 / $3.62 |

**读法**：
- 盲测 v1 已经参与过 Agent 提示词的设计，不能再作为证据。
- 两个干净的集合给出的信号不同：
  - 单点问题为主的盲测 v2.1 上，两套配置持平；
  - 一句话连问好几件事的盲测 v3 上，Agent 多答对 6 题。
- 合起来是 Agent 25/30，单次 RAG 19/30。差距全部来自多问题的题：单次 RAG 只检索一次，通常只拿到第一问的证据。
- 按问题形态路由看起来合理，但在独立的盲测 v5 上，路由 v1、v2 都没有比全部走 Agent 更划算（Agent 14/17，$2.40；最好的路由 14/17，成本相同或更高，延迟更长）。原因是级联每题都要先付单次 RAG 和检查的钱。所以当前默认全部走 Agent；有真实流量数据后再评估路由。详见 `reports/route_summary.md`。
- 前提仍是样本小，而且盲测题都由模型编写。学习者本人写的题可以作为另一批，单独检验。
