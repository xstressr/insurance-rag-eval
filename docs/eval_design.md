# 评测设计（一页）

> 2026-09-27。这一页说明本项目怎么判断一次改动“有没有用”。各实验的具体数字见 `reports/`，改进前后对比见 [before_after.md](before_after.md)。

## 1. 评什么

| 层 | 问题 | 指标 | 判定方式 |
|---|---|---|---|
| 检索 | 证据有没有进前 k 名 | Hit@5、Recall@5、MRR@10 | 程序：按条款号 + 页码匹配标注 |
| 上下文 | 模型看到的材料够不够回答 | 上下文命中率、证据完整率 | 程序 |
| 生成 | 答得对不对 | 正确 / 部分 / 错误；可回答题正确率 | LLM 评委，对照答案要点 |
| 生成 | 有没有编造 | 忠实度（每句话能否在给定片段里找到依据） | LLM 评委，与正确性分开判 |
| 生成 | 该不该拒答 | 误拒率、正确拒答率 | 程序 + 评委 |
| 引用 | 数字是否出自它引用的那一块 | 未引用 / 张冠李戴 / 上下文中不存在 | 程序（`citecheck.py`） |
| 工具 | 计算对不对、调用是否合法 | 答案与人工推算是否一致、参数校验失败率 | 程序 |
| 安全 | 越权、跨租户、注入、个人信息 | 不泄露 且 正常作答 | 程序 + 工具层拒绝记录 |
| 运行 | 能不能上线 | P50/P95 延迟、每千题成本、错误率 | 程序（`ops_report.py`） |

**正确性和忠实度分开判。** 一个答案可能全部有据可查，却漏了要点；也可能要点都对，却混进了片段里没有的内容。合成一个分数，就分不清是检索、上下文还是生成出的问题。

## 2. 评测集

| 集合 | 题数 | 角色 |
|---|---|---|
| golden_v1 / v2 | 33 | 开发集，可以用来调参 |
| golden_blind_v1 | 18 | 原本是盲测集。后来 a2 提示词的例子取自它的失败题，从那以后只作参考 |
| golden_blind_v2 / v2.1 | 16 | 干净的验证集（已用过一次）。v2.1 只改了 c06：学习者看过系统输出后裁定，新旧两版结果都报告 |
| golden_blind_v3 | 20 | 由其他模型（kimi、qwen、muse-spark）出题，按事先写定的规则去重并用固定种子抽样，Claude 不挑题（`dataset/blind_v3_protocol.md`） |
| judge_calib_v1 | 15 | 评委校准：人工给出预期判定，在调评委之前锁定 |
| tool_tasks_v1 | 10 | 计算工具，标准答案人工推算 |
| security_cases_v1 / v2 | 12 | 身份、隔离、注入、个人信息，外加正常对照题 |

题型覆盖五类：数字、精确查找、条件判断、跨产品对比、应拒答（条款没写，或问的是条款以外的产品）。

每道题附有：
- 证据条款号和页码；
- 答案要点；
- 条款原文摘录；
- 标注方法和标注人（`verified_by`，如实记录是 AI 还是学习者）。

## 3. 规则（防止自己骗自己）

1. **先锁题，再标注，再运行。** 盲测题写好后单独提交，然后才标注；运行只在标注之后。
2. **不因为结果改题。** 不能因为检索或生成的结果删题、换题、改标注。
   - 真有歧义的题可以剔除，但要写明原因，并报告剔除前后的指标。
   - 标注确实错了，就升版本（例如 golden_v2、security_cases_v2），新旧两版的结果都报告。
3. **选参规则事先写死。** 例如加权融合实验：先比 Hit@5，再比 MRR，打平时选更简单的配置。这条规则在运行前定死，在开发集上选参，盲测集只跑一次。
4. **单变量实验。** 每次只改一个因素，并先做回归检查：关掉新功能后，结果要与旧版逐条一致（靠缓存命中来证明）。
5. **事后决定要写明。** 看了结果之后才做的判断，报告里明确标注“事后”。
6. **一个集合用过一次就算污染。** 参与过决策的集合降级为参考，下一次验证要换新题。

## 4. LLM 评委

- **配置。** 评委用 GLM-5.3，思考强度 max，temperature 0；被评的系统用 DeepSeek V4.1 Flash。评委和系统来自不同厂商。
- **评分规则（j2）。**
  - 先查答案有没有与要点矛盾，矛盾一律判错，不能因为“大部分对”而判部分正确。
  - 拒答题看拒答内容：只说“无法回答”但漏掉关键说明的，判部分正确。
- **规则是怎么定下来的。**
  - j1 太宽松：锁定的校准集 14/15，对抗测试（改错数字或结论、追加片段里没有的内容）4/6。
  - 改成 j2 后：校准集 15/15，对抗测试 6/6。j2 定稿后又新构造了 5 条留出用例，也全部判对。
  - 把思考强度调高没有用。问题出在评分规则有歧义，不在评委推理不够。
- **已知盲区。** 评委看不到系统提示里的资料范围说明，会把“资料包含行业规范”这类话判为没有依据（agent_v2 的 q033）。

## 5. 结果怎么读

- **样本小。** 一个配置 12～33 题，相差 1～2 题在噪声范围内。结论只写“持平 / 明显更好 / 明显更差”。
- **每个配置只跑一次。** temperature 为 0 加缓存，保证了结果能复现，但看不出模型本身的波动。重要结论应该跑 3 次（见 BACKLOG）。
- **成本按列表价换算。** 本项目实际用的是订阅套餐，报告里的美元数是按官方 API 列表价换算的等价成本。
